# システム概要

## システム構成概要

本システムは、フィルム写真愛好家、現像ラボ（MiniLab）、写真専門家をシームレスに繋ぐマルチテナント型の統合プラットフォームです。クライアント層には「マルチフロントエンド構成」を採用し、愛好家向けにはクロスプラットフォーム対応のモバイルアプリ、現像ラボおよび管理者向けには機能豊富なWebポータルを提供します。バックエンドは、ビジネスロジックを集中処理する「ASP.NET Core Web API / Node.js」によるAPIサーバーを中核に据え、リアルタイム通信を担うSocket.ioサーバーを併設しています。また、画像解析（コンピュータビジョン）やRAGアシスタント、パーソナライズ推薦等の重い処理を担当する「AIエンジン」を独立したマイクロサービスとして配置し、API Gatewayを介して非同期的に連携することで、高負荷時でも高いスケーラビリティと耐障害性を維持するアーキテクチャを構築しています。

## 使用技術スタック

【フロントエンド】
- モバイルアプリ: Flutter (iOS / Android)
- Webポータル (ラボ/管理者用): ReactJS / Next.js (TypeScript)

【バックエンドAPI・リアルタイム通信】
- 主要フレームワーク: Java SpingBoot
- リアルタイム双方向通信: Socket.io

【データストア】
- リレーショナルデータベース: PostgreSQL (取引、ユーザー、マスター管理用)
- ベクトルデータベース: pgvector 又は 独立したベクトルDB (RAG、セマンティック検索用)
- クラウドストレージ: Azure Blob Storage 又は Firebase Storage (大容量スキャン画像、ネガデータ保管用)

【AI・機械学習】
- 画像解析: OpenCV, PyTorch / TensorFlow (コンピュータビジョンによるスキャン画像品質評価用)
- 自然言語処理 (RAG): LangChain, OpenAI API / Azure OpenAI Service (写真技術相談チャット用)

【インフラ・デプロイ】
- コンテナ技術: Docker, Azure Container Apps (オートスケーリング対応)
- CI/CD: GitHub Actions
- 監視・ログ: Azure Monitor, Application Insights

## システム間連携

本プラットフォームの価値を最大化するため、以下の外部サービスとのAPI/Webhook連携を実装します。
1. 配送パートナー連携 (Ahamove / Lalamove等):
注文承認時にラボからの集荷リクエストを自動送信。配送業者の配送状況に変動があった際、Webhookレシーバーがリアルタイムにステータス（配達中、完了等）を受信し、システム側の注文情報・地図情報を更新します。
2. オンライン決済・エスクロー決済ゲートウェイ連携 (Stripe, VNPay, Momo等):
顧客のクレジットカード情報等は一切自システム内に保持せず、PCI-DSS準拠のトークン決済を採用。中古カメラ等のマーケットプレイス取引においては、エスクロー（仮受・預託金）制御APIにより、受取完了後にシステムが自動で手数料（料率制御対応）を控除し、出品者口座へ売上を移動する安全な決済モデルを実現します。

## データフロー概要

主要データフローは以下の3つに分かれます。
1. 【現像・スキャン注文納品フロー】: 愛好家がアプリから注文を作成しオンライン決済完了 → ラボが受領しステータス更新（リアルタイムプッシュ通知） → ラボスタッフがフォルダ単位でスキャン画像をWebポータルへ一括アップロード → CV（コンピュータビジョン）エンジンが自動で画質（ゴミ、傷、ピンボケ等）を一時評価 → スコア閾値以下の場合はラボ端末に再スキャンアラート、正常時は顧客アーカイブへ即時同期 → 顧客は透かし入り画像をプレビュー確認し「検収承認」することで、オリジナルデータへのアクセス権（ZIP一括ダウンロード）が付与されます。
2. 【中古機材エスクロー取引フロー】: 購入申請と仮決済（仮受ステータス） → 出品者が配送手続きと追跡番号登録 → 購入者が受取・動作確認完了を入力 → システム手数料自動控除 → 出品者売上高確定（深夜バッチで集計・送金処理）。
3. 【AI RAGアシスタントフロー】: 専門家の承認済み記事やQ&Aのベストアンサーを定期パースしてベクトルDBに自動同期。愛好家からの自然言語の疑問に対して、セマンティック検索とLLMにより論理的な推奨回答を生成。

## セキュリティ概要

大容量データと金銭・機材取引を安全に行うため、多層防御のセキュリティ対策を講じます。
- 認証とロールベース認可 (RBAC): JWT（JSON Web Token）およびOAuth2を組み合わせてセッションを管理。愛好家、ラボ、専門家、配送、管理者、モデレーターの各ロールに基づき、APIレベルおよびUIコンポーネントレベルでアクセス・操作権限を厳格に制御します。多要素認証（MFA）もサポート。
- 暗号化: 通信はすべてHTTPS/WSSを強制（TLS 1.3推奨）。Azure Blob StorageおよびPostgreSQL内の顧客データ・スキャンデータは、AES-256規格等を用いて静止時暗号化を実施します。
- 決済・取引保護: クレジットカード情報の非保持化と、エスクロー決済ロジックの実装により不正取引を未然に防止。クレーム発生時には、システム管理者が取引を「保留（Hold）」に変更し送金対象外とする制御フラグシステムを配備します。
- 投稿モデレーション: コミュニティや中古機材の規約違反に対して「不適切コンテンツ自動非表示/通報機能」を搭載し、管理者ポータルから一括でBAN、削除などの処置を行えます。

## インフラ構成概要

大量の画像・データの拡張性に耐えうる、Azureベースのクラウドネイティブなインフラ構成を構築します。
- オートスケーリング: APIおよびAI処理エンジンはコンテナ化（Docker）され、Azure Container Apps上で稼働。CVモデルによるバッチやRAGへのアクセス集中時も自動でコンテナが水平スケーリングします。
- 高可用性データベース: マネージドサービス（Azure Database for PostgreSQL）を採用し、稼働率99.5%を維持。データベースのフルバックアップは日次で自動実行され、地理冗長ストレージ（GRS）へ30日間保存。スキャン画像等は制限なくスケールアウト可能なAzure Blob Storageに多重保存します。
- キャッシュと配信: 全世界からの画像プレビューを高速化するため、CDNを前段に構築。また、保管ポリシーに基づく「データクリーンアップバッチ」をデイリーで実行し、無料保存期限を過ぎた高解像度データをコールドストレージへ自動退避させ、ストレージコストを最適化します。
- 運用監視とCI/CD: Azure MonitorとApplication Insightsを連携し、APIのエラー（5xx）発生時や高負荷時にSlack/Teamsへ自動アラートを配信。GitHub Actionsを利用したCI/CDにより、ユニットテスト（カバレッジ70%目標）をパスした成果物をゼロダウンタイムで継続的デプロイします。
