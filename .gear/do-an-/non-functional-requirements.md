# 非機能要件一覧

| id | category | requirement | targetValue | priority |
| --- | --- | --- | --- | --- |
| NFR-001 | 性能 | 標準APIレスポンス時間 | 通常のWebおよびモバイルAPIリクエストの95%以上が、2秒以内に応答すること（※要確認：AIによる画像解析、セマンティック検索、RAGアシスタントなどの重い処理を除く）。 | 高 |
| NFR-002 | 性能 | 大容量スキャンデータの一括転送性能 | フィルム1本分（約36枚、高解像度スキャンデータ計約200MB〜300MB相当）のアップロード/ダウンロードにおいて、安定したネットワーク環境下で5分以内に完了すること。※要確認 | 中 |
| NFR-003 | 性能 | 同時接続ユーザー数（同時並行処理能力） | リリース初期段階において、アクティブユーザー数1,000人、ピーク時同時アクティブセッション数300人を許容できること。※要確認 | 中 |
| NFR-004 | 性能 | AI推薦および検索の応答時間 | AIパーソナライズ推薦結果および自然言語セマンティック検索結果の提示は、リクエスト送信から3秒以内に完了すること。※要確認 | 中 |
| NFR-005 | 可用性 | 稼働率（アップタイム） | 年間稼働率99.5%以上を維持すること（計画メンテナンス、計画外の決済・配送ゲートウェイ側ダウンタイムを除く）。※要確認 | 高 |
| NFR-006 | 可用性 | 目標復旧時点（RPO）および目標復旧時間（RTO） | システム重大障害発生時、RPO（データ損失許容時間）は最大24時間以内、RTO（システム復旧時間）は最大12時間以内とすること。※要確認：ビジネスルール未定義のため暫定 | 高 |
| NFR-007 | 可用性 | データバックアップ体制 | PostgreSQLデータベースのフルバックアップを日次で自動実行し、地理冗長ストレージへ最低30日間保存すること。デジタルスキャンデータはクラウド（Azure Blob / Firebase）上で多重化保存すること。※要確認 | 高 |
| NFR-008 | セキュリティ | エンドツーエンドの安全な認証および認可制御 | JWT（JSON Web Token）およびOAuth2を用いたセキュアなセッション管理を行い、ロールベースアクセス制御（RBAC）により、各ユーザー（愛好家、ラボ、専門家、配送、管理者）の権限に応じたアクセス制限を完全に強制すること。 | 高 |
| NFR-009 | セキュリティ | 通信および保存データの暗号化 | すべてのクライアント・サーバー間通信においてHTTPS（TLS 1.3推奨）およびWSSを強制すること。Azure Blob Storage / Firebase Storageに保存されるスキャン画像および個人情報は、AES-256規格等を用いて静止時暗号化を施すこと。 | 高 |
| NFR-010 | セキュリティ | 決済およびエスクロー情報の安全性 | プラットフォーム内に決済カード情報を直接保存せず、国際基準（PCI-DSS）に準拠した外部決済ゲートウェイ（Stripe、VNPay、Momo等）のトークン決済仕様を採用すること。※要確認：決済ルール未定義のため暫定 | 高 |
| NFR-011 | 拡張性 | クラウドストレージのオートスケーリング | 画像アーカイブ容量の急増に対応するため、クラウドオブジェクトストレージの制限なきスケールアウト性能を利用し、運用開始後数テラバイト（TB）規模の拡張が設計変更なしに可能であること。 | 高 |
| NFR-012 | 拡張性 | AIサービスおよびAPIコンテナの水平スケーリング | CVモデルによる画質判定バッチ処理や、RAGアシスタントへのリクエストバースト時、コンテナオーケストレーション（Azure Container Apps等）により自動的にバックエンドインスタンスをスケーリングすること。※要確認 | 中 |
| NFR-013 | 運用 | システムログ・監査ログの保持基準 | 取引ログ、決済ステータス変更履歴、管理者操作ログ、セキュリティ関連イベントログは、コンプライアンス順守のため最低7年間保持すること。通常のデバッグ・アクセスログは30日間保持。※要確認：ビジネスルール未定義のため暫定 | 高 |
| NFR-014 | 運用 | システムパフォーマンスおよびエラー監視・アラート | クラウド監視サービスを統合し、リソース使用率が80%を超える、またはAPIのエラー（5xx）発生率が1%を超えた場合、開発/保守チームへ即時自動アラート（Slack/Teams等）を通知すること。※要確認：運用制約未定義のため暫定 | 中 |
| NFR-015 | 運用 | CI/CDパイプラインによる継続的デプロイ | GitHub Actionsを利用して、ビルド、テスト、およびAzure環境へのデプロイを自動化すること。テストコードのカバレッジ目標値はフロントエンド、バックエンドともに最低70%以上とすること。※要確認 | 中 |
| NFR-016 | 移行 | 既存フィルムラボ情報の初期移行計画 | 未定義（※要確認：すでに個別運用しているラボの店舗情報や顧客リスト等を初期データとして一括インポートする仕組み、またはCSVフォーマットの提供要否）。 | 低 |
| NFR-017 | 移行 | AIモデルアップデートにおけるゼロダウンタイム移行 | 推薦アルゴリズムモデル、ベクトルDB（RAG）、およびコンピュータビジョン（CV）の画質解析モデルを更新する際、システム全体を停止することなくバックグラウンドで切り替えを行える設計であること。 | 中 |
